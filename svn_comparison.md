# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто указатель (ссылка) на определённый коммит. Создание ветки занимает байты и происходит мгновенно, потому что вся история хранится локально.

В SVN ветка — это физическая копия директории на сервере. При создании ветки сервер копирует файлы, что занимает время и место. Поэтому в SVN ветки создают редко и неохотно.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система: все коммиты отправляются на центральный сервер. Без подключения к серверу коммит невозможен.

В Git коммит делается локально (в своей копии репозитория), а синхронизация с сервером (push) — отдельный шаг. Поэтому в Git можно работать офлайн: делать коммиты, ветки, смотреть историю.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты: если проект годами ведётся в SVN, миграция может быть дороже, чем поддержка.
- Жёсткий контроль доступа: в SVN можно ограничить доступ к отдельным директориям, в Git — только ко всему репозиторию.
- Большие бинарные файлы: SVN умеет хранить их без раздувания истории (хотя сейчас есть Git LFS).
- Простые линейные проекты: для маленьких команд без сложного ветвления SVN может быть проще в освоении.
- Госсектор и банки: там часто консервативные требования и старые системы.
